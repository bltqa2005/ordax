# ORDAX / TEAM INTELLIGENCE

Аналитический сайт команды OrdaX по Counter-Strike 2 на данных FACEIT.
Стек: Next.js 14 (App Router), React, TypeScript, Tailwind CSS, Recharts, Framer Motion, Lucide.

## Статус проекта (важно прочитать)

- Код написан без возможности установить пакеты и собрать проект, поэтому `npm run build` и интерфейс в браузере **не проверялись**.
  Логика (клиент FACEIT, кэш, снимки ELO, расчёты, OPI) прогнана на локальной заглушке API: 8 игроков загружаются, 2 нештатных случая обрабатываются (профиль не найден, ник не совпал), кэш и ограничение частоты работают.
- Формат ответов реального FACEIT API я не проверял. Парсеры написаны по документации (пути и лимиты сверены со swagger) и осторожны: если поле не найдено, показывается N/A, а не число.
- В `next.config.mjs` включено `typescript.ignoreBuildErrors`, чтобы мелкая ошибка типов не блокировала деплой. После первого запуска выполни `npm run typecheck`, исправь замечания и выключи оба флага.
- Без ключа FACEIT сайт честно показывает **API NOT CONFIGURED** и N/A везде. Деморежима и выдуманных цифр нет.

## Запуск локально

```bash
npm install
cp .env.example .env.local      # впиши FACEIT_API_KEY
npm run dev                     # http://localhost:3000
```

Сборка: `npm run build && npm start`.

## Ключ FACEIT

1. Зайди на https://developers.faceit.com, создай приложение.
2. Создай **Server side API key** и положи в `FACEIT_API_KEY`.
3. Ключ используется только в серверных маршрутах (`src/lib/faceit.ts`). В браузер, в публичные файлы и в Git он не попадает (`.env*` в `.gitignore`).

## Переменные окружения

| Переменная | Зачем |
| --- | --- |
| `FACEIT_API_KEY` | Серверный ключ FACEIT Data API (обязательно) |
| `CACHE_TTL_SECONDS` | Сколько секунд сервер не ходит в FACEIT повторно (по умолчанию 300) |
| `FACEIT_CONCURRENCY` | Параллельные запросы к FACEIT (по умолчанию 3) |
| `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` | Постоянное хранилище снимков ELO (для Vercel) |
| `DATA_DIR` | Папка для JSON-хранилища на VPS/Docker (по умолчанию `./.data`) |
| `ADMIN_TOKEN` | Нужен для ручного подтверждения профиля игрока |
| `CRON_SECRET` | Нужен для запросов к `/api/cron` от планировщика |

## Деплой на Vercel (бесплатно)

1. Залей проект в репозиторий GitHub и импортируй его на vercel.com.
2. В Settings → Environment Variables добавь `FACEIT_API_KEY`.
3. **Историю ELO нужно хранить вне сервера**: на Vercel файловая система временная. Создай бесплатную базу Upstash Redis (через Vercel Marketplace или upstash.com) и добавь `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN`. Без этого снимки теряются при перезапуске, графики ELO будут пустыми.
4. Ссылка вида `https://твой-проект.vercel.app` и есть **общая ссылка на команду**: открывается с телефона и ПК. Раздел можно открыть напрямую: `/#leaderboard`.

## Как работает получение данных

Серверный слой: `src/lib/faceit.ts` (клиент), `src/lib/team.ts` (сбор, кэш, снимки), `src/app/api/*` (маршруты).

Для каждого игрока:

1. Поиск по точному нику: `GET /players?nickname=…&game=cs2`. Возвращённый ник сверяется с указанным. При несовпадении или отсутствии профиля игрок помечается `mismatch` / `not_found`, и на карточке появляется форма ручного подтверждения Player ID (нужен `ADMIN_TOKEN`).
2. Player ID сохраняется, повторные поиски по нику не делаются.
3. `GET /players/{id}`: ELO, Level, аватар, ссылка на профиль.
4. `GET /players/{id}/stats/cs2`: общая статистика (матчи, победы, Win Rate, K/D, HS %).
5. `GET /players/{id}/games/cs2/stats`: до 200 последних матчей (две страницы по 100; больше API не отдаёт одним способом без смещения > 200). Из них считаются периоды 7D/30D/90D, серии, активность и «последние 3 матча».
6. `GET /players/{id}/history`: время начала, конец и счёт для расчёта длительности последних матчей.

Надёжность: кэш на сервере (`CACHE_TTL_SECONDS`), ручной Refresh не чаще раза в 30 секунд, не более `FACEIT_CONCURRENCY` параллельных запросов, до 4 попыток при 429/5xx/сетевых сбоях, защита от некорректного JSON. Если обновление игрока не удалось, показываются его прошлые данные с пометкой.

Автообновление на клиенте (5/15/30 минут) не работает, пока вкладка скрыта.

## Что FACEIT API не отдаёт (и что сайт делает вместо выдумок)

- **Изменение ELO по матчам и прошлые значения ELO.** Их нет в официальных методах. Поэтому ELO-динамика строится по **снимкам**: при каждом реальном обновлении сайт сохраняет текущий ELO. Пока снимков меньше двух, показывается N/A и пояснение. Чтобы история копилась без посетителей, вызывай по расписанию `GET /api/cron` с заголовком `Authorization: Bearer <CRON_SECRET>` (любой планировщик, например cron-job.org раз в 30 минут).
- **Фильтр истории по диапазону ΔELO** отключён по той же причине.
- Kills / Deaths / Assists считаются по загруженной выборке матчей (до 200), а не за всю жизнь аккаунта. На экране это указано.
- ADR и некоторые поля показываются, только если пришли в ответе.
- Уровни FACEIT и пороги ELO для прогресса до следующего уровня справочные.

## Что реализовано

Overview (7 карточек, Player of the Week, Biggest ELO Gain, Inactivity Radar, алерты), Roster (поиск, сортировка, карточки, последние 3 матча), профиль игрока (ELO, прогресс уровня, график ELO 7/30/90, статистика, раскрываемые матчи, Player timeline), Leaderboard (сортировка по 8 полям, период, фильтр по Level, CSV, ссылка), Match History (фильтры, группировка по ID матча), Analytics (распределения ELO и Level, Activity Monitor, Win Rate, Performance, Team Consistency, алерты с настраиваемыми порогами, Head-to-head), Methodology с формулой OPI и вкладом компонентов.

## OPI и Player of the Week

Формулы и веса показаны на сайте: Analytics → Methodology. OPI — внутренняя метрика OrdaX, не показатель FACEIT. При меньше 5 матчей за период OPI = N/A.
